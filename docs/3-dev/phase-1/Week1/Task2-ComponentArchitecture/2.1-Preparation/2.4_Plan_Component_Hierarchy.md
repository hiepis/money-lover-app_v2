# 2.4 Plan Component Hierarchy and Data Flow Patterns

## Overview

Plan the component hierarchy and data flow patterns to ensure a scalable and maintainable architecture.

## Prerequisites

- Understanding of React component composition.
- Familiarity with state management and data flow concepts.

## Steps

### 1. Define Component Hierarchy

- Identify the main components and their subcomponents.
- Create a visual representation of the component tree.

### 2. Plan Data Flow

- Determine the data flow between components (e.g., props, context, or state management).
- Document the data dependencies and relationships.

### 3. Validate the Plan

- Review the component hierarchy and data flow with the team.
- Ensure the plan aligns with the project requirements and design system.

## Expected Results

- A well-defined component hierarchy.
- A clear data flow plan that supports scalability and maintainability.

## Troubleshooting

### Common Issues

1. **Overlapping Responsibilities**: Ensure components have a single responsibility.
2. **Complex Data Flow**: Simplify data flow to avoid unnecessary complexity.

### Component Responsibility Matrix

**1. Layout Components:**
- **App**: Root component, global state management, routing setup
- **AppLayout**: Main layout structure, consistent margins/padding
- **Header**: App branding, current totals, global navigation
- **Navigation**: Bottom tab navigation, active state management
- **MainContent**: Page routing container, handles page transitions

**2. Feature Components:**
- **ExpenseForm**: Main expense entry form, form validation, submission
- **ExpenseList**: Display expenses, pagination, filtering
- **ExpenseItem**: Individual expense display, inline actions
- **CategoryManager**: Category CRUD operations, color management
- **SummaryCards**: Financial summaries, period calculations

**3. UI Components:**
- **Button**: Reusable button with variants (primary, secondary, success)
- **Input**: Form inputs with validation states and labels
- **Card**: Content containers with consistent styling
- **Modal**: Overlay dialogs with focus management
- **Loading**: Loading states and skeleton screens

**4. Specialized Components:**
- **AmountInput**: Currency-specific input with formatting
- **CategorySelector**: Category picker with icons and colors
- **FilterBar**: Date/category filtering interface
- **TotalDisplay**: Formatted financial totals

### Data Flow Architecture

**State Management Strategy:**
Based on React useState/useContext approach (no external libraries):

```javascript
// Global App State Structure
const AppContext = {
  // Core Data
  expenses: [],
  categories: [],
  
  // UI State
  currentPage: 'expenses',
  isLoading: false,
  error: null,
  
  // User Preferences
  currency: 'USD',
  dateFormat: 'MM/DD/YYYY'
}

// Local Storage Interface
const StorageContext = {
  saveExpenses: (expenses) => {},
  loadExpenses: () => {},
  saveCategories: (categories) => {},
  loadCategories: () => {}
}
```

**1. Top-Down Data Flow (Props):**
```
App (Global State)
├── provides: expenses, categories, currency
├── ExpenseForm
│   ├── receives: categories, onAddExpense
│   └── AmountInput
│       └── receives: currency, value, onChange
├── ExpenseList  
│   ├── receives: expenses, onEditExpense, onDeleteExpense
│   └── ExpenseItem
│       └── receives: expense, category, onEdit, onDelete
└── Navigation
    └── receives: currentPage, onPageChange
```

**2. Bottom-Up Data Flow (Events):**
```
ExpenseForm
├── onAddExpense(expense) → App.addExpense()
├── AmountInput
│   └── onChange(value) → ExpenseForm.setAmount()
└── CategorySelector  
    └── onSelect(category) → ExpenseForm.setCategory()

ExpenseItem
├── onEdit(expense) → ExpenseList.handleEdit()
└── onDelete(id) → ExpenseList.handleDelete()

Navigation
└── onPageChange(page) → App.setCurrentPage()
```

**3. Context-Based Data Flow:**
```javascript
// App Context Provider
<AppProvider value={{
  state: { expenses, categories, currentPage },
  actions: { addExpense, updateExpense, deleteExpense }
}}>
  <StorageProvider>
    <AppLayout />
  </StorageProvider>
</AppProvider>

// Component Usage
const ExpenseForm = () => {
  const { state, actions } = useContext(AppContext);
  const { saveExpenses } = useContext(StorageContext);
  
  const handleSubmit = (expense) => {
    actions.addExpense(expense);
    saveExpenses([...state.expenses, expense]);
  };
};
```

### Component Communication Patterns

**1. Parent-Child Communication (Props):**
```javascript
// Parent passes data down
<ExpenseList 
  expenses={expenses}
  categories={categories}
  onEdit={handleEdit}
  onDelete={handleDelete}
/>

// Child receives via props
const ExpenseList = ({ expenses, categories, onEdit, onDelete }) => {
  return expenses.map(expense => (
    <ExpenseItem 
      key={expense.id}
      expense={expense}
      category={categories.find(c => c.id === expense.categoryId)}
      onEdit={() => onEdit(expense)}
      onDelete={() => onDelete(expense.id)}
    />
  ));
};
```

**2. Context-Based Communication:**
```javascript
// Global state access
const ExpenseForm = () => {
  const { expenses, categories } = useContext(AppContext);
  const { addExpense } = useContext(AppActions);
  
  const handleSubmit = (formData) => {
    const expense = { ...formData, id: uuid(), date: new Date() };
    addExpense(expense);
  };
};
```

**3. Event-Based Communication:**
```javascript
// Custom hooks for complex logic
const useExpenseManager = () => {
  const [expenses, setExpenses] = useState([]);
  
  const addExpense = (expense) => {
    setExpenses(prev => [expense, ...prev]);
    localStorage.setItem('expenses', JSON.stringify([expense, ...expenses]));
  };
  
  const deleteExpense = (id) => {
    setExpenses(prev => prev.filter(e => e.id !== id));
  };
  
  return { expenses, addExpense, deleteExpense };
};
```

### Scalability Considerations

**1. Component Reusability:**
- UI components are fully reusable across features
- Business logic separated from presentation
- Consistent prop interfaces across similar components

**2. State Management Scaling:**
- Start with useState/useContext
- Easy migration path to Redux if needed
- Local storage abstraction for future cloud sync

**3. Code Organization:**
```
src/
├── components/
│   ├── Layout/         # AppLayout, Header, Navigation
│   ├── UI/             # Button, Input, Card, Modal
│   └── Forms/          # ExpenseForm, CategoryForm
├── pages/              # Page-level components
├── hooks/              # Custom hooks for logic
├── contexts/           # React contexts
├── utils/              # Helper functions
└── constants/          # App constants
```

### Performance Optimization Patterns

**1. Memoization Strategy:**
```javascript
// Expensive calculations
const MonthlySummary = memo(({ expenses }) => {
  const total = useMemo(() => 
    expenses.reduce((sum, expense) => sum + expense.amount, 0),
    [expenses]
  );
  
  return <div>Total: ${total}</div>;
});

// Callback optimization
const ExpenseList = ({ expenses, onDelete }) => {
  const handleDelete = useCallback((id) => {
    onDelete(id);
  }, [onDelete]);
  
  return expenses.map(expense => (
    <ExpenseItem 
      key={expense.id}
      expense={expense}
      onDelete={handleDelete}
    />
  ));
};
```
